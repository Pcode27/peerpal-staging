# Phase 58 — Therapist Referral Programme: Test Specification

## System overview

A therapist (referrer) shares a unique link. An applicant (future referred therapist)
clicks the link and completes the join form. When the referred therapist runs paid
sessions, the referrer earns a commission. Commissions are batched monthly and paid
via M-Pesa.

**This system is completely independent of the user referral system (Phase 46 / Seka).**

---

## Commission math

```
therapist_bookings.client_charge_kes  = what member pays
therapist_bookings.therapist_rate_kes = therapist receives (≈ 80 %)
therapist_bookings.platform_fee_kes   = PeerPal retains (≈ 20 %)

commission_kes = Math.round(platform_fee_kes * 0.05)
              = Math.round(PeerPal's 20% cut × 5%)
              = 1% of session value (before rounding)
```

Example: session KES 2 000  →  platform_fee KES 400  →  commission KES 20

## End-to-end flow (8 steps)

1. **Referrer signs addendum** → `POST /therapy/therapist/sign-addendum` →
   `addendum_signed_at`, `referral_code` written to `therapist_profiles`

2. **Referrer shares link** → `https://therapist.peer-pal.com/join?ref=CODE`

3. **Applicant resolves code** → `GET /therapy/referral-code/:code` (public, rate-limited)
   → returns `{ valid, referrer_name }`

4. **Applicant submits form** → `POST /therapy/referral-applications` (public, rate-limited)
   → row in `therapist_referral_applications` with `referrer_therapist_id`

5. **Admin creates therapist account** (Phase 58.8 — NOT YET BUILT)
   → new `therapist_profiles` row with `referred_by_therapist_id = referrer_therapist_id`
   from the application row. **Without this step commissions never fire.**

6. **Sessions run → escrow releases** → `runEscrowReleaseJob()` (hourly) →
   if guards pass, inserts into `therapist_commissions`

7. **Monthly payout** → `runReferralPayoutJob()` (1st of month, 09:00 EAT / 06:00 UTC)
   → creates `therapist_commission_payouts`, marks commissions `paid`

8. **Referrer sees balance** → `GET /therapy/therapist/my-commissions` (therapistAuth)

## Commission engine guards (all must pass)

| Guard | Implementation |
|-------|---------------|
| Referrer exists | `referred_by_therapist_id IS NOT NULL` |
| Referrer signed addendum | `referrer_addendum_signed_at IS NOT NULL` |
| No self-referral | `referred_by_therapist_id <> therapist_id` |
| Non-zero session fee | `platform_fee_kes > 0` |
| Within 12-month window | `session_ended_at <= addendum_signed_at + 1 year` |
| Idempotency | `ON CONFLICT (booking_id) DO NOTHING` |

---

## Payout job guards

| Guard | Implementation |
|-------|---------------|
| Pending commissions only | `WHERE tc.status = 'pending'` |
| Not already batched this month | `NOT EXISTS (... period_month = $1)` |
| Positive total | `HAVING SUM(tc.commission_kes) > 0` |
| M-Pesa number present | runtime skip if `mpesa_number IS NULL` |
| Exact batch scope | `UPDATE WHERE id = ANY(commission_ids)` — pins rows from aggregate |
| Idempotency | `ON CONFLICT (referrer_therapist_id, period_month) DO NOTHING` |
| Atomic | `transaction()` wraps insert + update |

## Isolation from user referral system (Phase 46)

| Dimension | User referral (Phase 46) | Therapist referral (Phase 58) |
|-----------|--------------------------|-------------------------------|
| Trigger | User signup with `?ref=CODE` | Therapist applies with `?ref=CODE` |
| Code stored on | `users.referral_code` | `therapist_profiles.referral_code` |
| Code generated by | `generateReferralCode()` | `generateTherapistReferralCode()` |
| Reward table | `referral_rewards` | `therapist_commissions` |
| Reward currency | Credits | KES (M-Pesa) |
| Payout table | n/a (credits) | `therapist_commission_payouts` |
| Service file | `services/referrals.js` | `jobs/escrowReleaseJob.js`, `jobs/referralPayoutJob.js` |
| Route file | `routes/auth.js`, `routes/credits.js` | `routes/therapy.js` |

Code format is the same (6-char base36) but checked against different tables — no collision risk.

## RLS

All three Phase 58 tables have RLS enabled with **no permissive policies**:
- Supabase anon key → 0 rows returned (safe for client-side Supabase SDK use)
- Backend (service role) → bypasses RLS → all queries work

Tables: `therapist_referral_applications`, `therapist_commissions`, `therapist_commission_payouts`

## Known gaps (open items)

### 58.8 — Admin handoff (NOT BUILT)
When admin creates a therapist account from an application, the application's
`referrer_therapist_id` must be copied to `therapist_profiles.referred_by_therapist_id`.
Without it the commission engine never fires. This is the single most critical
functional gap in Phase 58.

### Commission reversal (NOT BUILT)
Schema supports `status = 'reversed'` and `reversed_reason = 'refund'`, but no
code sets it. If a session booking is disputed and resolved as a full refund,
any commission earned from that booking is not reversed. Business decision needed.

### Payout UPDATE race (mitigated)
The aggregate SELECT now captures `commission_ids`; the UPDATE uses
`WHERE id = ANY(commission_ids)`. Any commission inserted after the SELECT
stays `pending` and is swept in the next month's run. Documented and acceptable.
